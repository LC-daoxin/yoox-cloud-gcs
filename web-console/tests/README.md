# 前端验证

在 `web-console` 目录执行：

```sh
npm test
npm run test:multi-device
npm run test:dashboard
npm run build
```

`npm test` 覆盖地图坐标、WHEP 超时/取消，以及双视频会话的隔离、缓存、偏好、故障恢复和退出清理。

`test:multi-device` 启动本地 Vite，使用配置中的本机 Chrome。所有设备 HTTP、WebSocket 和 MQTT 接口均被测试夹具拦截，不连接现场设备。视频用两个 Canvas 生成不同画面，通过实际 `RTCPeerConnection` 在本机发送和解码。

双设备测试包含：

- 100 次热切换：视频轨道 ID 保持不变，只创建两个 WHEP 会话，不重复发送镜头、清晰度或启动/停止命令；点击到目标画面 ready 的 P95 小于 500 ms。
- 两路首帧不会被延迟的清晰度响应遮挡；设备各自保存清晰度偏好。
- 视图切换保持 A 的 DRC 会话和心跳，不给 B 抢权、进入 DRC 或发送控制向量；原有接管归零、退出确认和任务隔离测试继续执行。
- 正常退出关闭两个浏览器 reader；退出时尚未完成的冷启动会在返回后清理所属设备推流。

截图和 `warm-switch-timing.json` 位于 `test-results/multi-device/`，不提交这些生成文件。本机合成视频的耗时用于回归，不代表真实设备端到端延迟。

经用户另行授权部署后，应在两台真实设备上验证：标清/高清、变焦/红外、断网重连、页面前后台、不同目标浏览器，以及双路接收的 CPU/带宽占用。仅已预热且持续解码的会话适用热切换目标；冷启动单独计时。

`test:dashboard` 使用布尔在线状态和模拟上下线事件验证首页计数，并完全禁用 WebGL/WebGL2 验证 Canvas 兼容地图。底图瓦片和中文字体来自本地 `/maps/`（Vite 默认代理到 localhost:8080），检查实际绘制像素、设备标记、WGS84 选点和地图包缺失提示。设备与飞控接口全部拦截，断言没有写请求或站外资源请求。

预览布局与最近查看缓存回归：`test:multi-device` 包含地图优先隐藏小窗后跨越 7 秒看门狗窗口的持续解码检查，验证两路视频轨道 ID 不变、不重建 WHEP；三设备 A→B→C 的小窗保留 B，拓扑刷新不改变最近查看顺序，A 的飞控会话不受视频缓存淘汰影响。
