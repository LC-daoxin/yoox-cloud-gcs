# YOOX Cloud GCS 文档同步与交付规范

> 状态：当前维护规范
> 更新日期：2026-10-15

文档是版本制品。配置、API、部署脚本或设备协议发生变化时，相关文档必须在同一变更中更新，
不能依靠后续人工补写。

## 1. 当前文档入口

`docs/README.md` 是文档总索引，负责标明每份文档的用途、状态和权威程度。README、API Portal、
Swagger/OpenAPI 和 Nano 离线包中的 README 也应链接到对应的当前指南。

文档分为三类：

- **当前操作文档**：可以直接按步骤执行，如配置、API、运维、macOS/Linux/Nano 部署；
- **诊断与联调文档**：针对 MQTT、指令链路、Python Demo 和 a-uav 接入；
- **背景与规划文档**：记录方案和里程碑，不代表当前代码已经实现。

背景文档必须在开头显式注明“规划基线”或“历史评审”，避免被当成当前运行手册。

## 2. 事实来源

| 内容 | 首要事实来源 | 对应文档 |
| --- | --- | --- |
| 镜像、服务、端口、卷、profiles | `compose.yml`、`compose.nano.yml` | 04、06、08、10、11、13 |
| 环境变量 | `.env.example`、`application.yml`、Compose | 06 |
| HTTP API | Controller/接口注解、运行时 `/v3/api-docs` | 07 |
| WebSocket | WebSocket 配置、前端连接代码 | 07、14 |
| MQTT Topic 和方法 | MQTT 模型、生产/消费处理器、EMQX ACL | 07、14、15 |
| Nano 离线包 | `build-nano-offline-bundle.sh`、`install.sh`、镜像清单 | 13 |

| a-uav 状态 | 指定提交的 Android 源码 | 16 |

冲突时以运行代码和生成的 OpenAPI/Compose 结果为准，并修正文档。规划文档中的目标不能覆盖当前
实现事实。

## 3. 变更同步矩阵

### 3.1 Compose、镜像或端口变化

同一变更至少检查：

- `README.md`；
- `docs/04-部署与容量规划.md`；
- `docs/06-配置指南.md`；
- `docs/08-部署运维指南.md`；
- `docs/10-macOS本地构建与部署.md`；
- `docs/11-Linux本地构建与部署.md`；
- `docs/13-Nano快速部署.md`；
- `offline/nano-deploy/README.md`。

修改离线包所需配置后运行：

```bash
bash scripts/sync-offline.sh
```

### 3.2 环境变量变化

必须同时更新：

1. `.env.example`；
2. Compose 或 `application.yml` 的读取逻辑；
3. `docs/06-配置指南.md`；
4. `offline/nano-deploy/.env.example`；
5. 相关预检逻辑和部署示例。

敏感值只写占位符和生成方式，不写真实密钥。项目明确要求纳入版本库的受控现场配置，应在文档
索引中标为敏感文件，并限制仓库访问范围。

### 3.3 HTTP API 变化

必须同时更新：

1. Controller/接口及测试；
2. `docs/07-API指南.md` 中的业务流程或示例；
3. Python Demo 或前端调用；
4. API Portal 中相关说明；
5. 运行时 OpenAPI 契约。

`docs/07-API指南.md` 是场景化指南，不重复手工维护每一个 DTO 字段。完整路径、参数和 Schema 以
`/v3/api-docs` 为准。

### 3.4 MQTT、WebSocket 或飞控行为变化

至少检查：

- `docs/07-API指南.md`；
- `docs/14-指令链路诊断日志指南.md`；
- `docs/15-MQTT直连AB测试指南.md`；
- `docs/python-demo/README.md` 和相关 Demo；
- `docs/16-a-uav上云服务接入分析与实施方案.md`。

飞控示例必须保留人工确认、状态恢复、幂等和超时后查询状态等安全说明。

## 4. 版本和状态标记

当前操作文档开头至少记录适用版本或事实来源和更新日期。历史评审必须记录：

- 评审日期；
- 被评审仓库、分支和提交；
- 后续是否已修复；
- 哪些结论仍有效。

禁止用“当前”“现网”描述已经过期且未复验的结果。此类内容应改为带日期的历史记录。

## 5. API 和事件文档

- Swagger UI：`/swagger-ui/index.html`；
- OpenAPI JSON：`/v3/api-docs`；
- Markdown API 指南：解释登录、直播、DRC、控制、航线、媒体和恢复策略；
- API Portal：面向离线交付的静态开发文档。

当前仓库没有独立 AsyncAPI 文件，不得在交付清单中声称已经生成。MQTT/WebSocket 契约目前由
代码、API 指南、诊断文档和示例共同维护；后续引入 AsyncAPI 时再增加对应校验。

## 6. 离线包文档

Nano 离线包必须包含：

```text
README.md
VERSION
IMAGE-MANIFEST.txt
install.sh
deploy/
images/
```

发布前至少验证：

- 镜像清单数量和实际 `docker save` manifest 一致；
- 全部镜像为 `linux/arm64`；
- `.env.template` 是否包含占位符或明文现场密钥；
- 安装命令与 `install.sh` 参数一致。

## 7. 安全要求

- 不新增未授权的真实密码、Token、License、设备 SN、客户 IP 或精确作业坐标。
- 示例使用 `<server-ip>`、`<gateway-sn>`、`<workspace-id>` 等占位符。
- 日志示例必须删除 JWT、MQTT 密码、签名 URL 和应用凭据。
- 含现场配置的文件必须明确标记敏感性，仓库和制品仅限授权人员访问。
- 删除 Word/PDF 等静态副本后，不保留会继续生成旧内容的硬编码脚本。

## 8. 校验要求

提交前至少运行：

```bash
git diff --check
env JAVA_HOME=$(/usr/libexec/java_home -v 17) make verify   # macOS
```

并检查：

- Markdown 本地链接存在；
- 命令引用的脚本和路径存在；
- 端口、镜像和变量与 Compose 一致；
- API 示例路径与 Controller/OpenAPI 一致；
- 文档未重新引入已删除的旧流程或敏感内容。

涉及集成部署时，再运行 `make up` 和 `make smoke`。只改背景说明时可不启动完整服务，但仍要完成
链接和事实一致性检查。

## 9. 发布验收

- 文档总索引能区分当前手册、诊断文档和历史规划。
- 配置指南覆盖 `.env.example` 中的公开配置。
- API 场景示例与运行时 OpenAPI 不冲突。
- 运维文档区分源码部署与 Nano 离线部署。
- 离线包无需目标 Nano 联网即可安装、更新和回滚。
- 文档中没有无说明的历史 IP、设备标识或默认生产凭据。
