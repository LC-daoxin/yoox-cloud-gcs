# YOOX Cloud GCS 部署与容量规划

> 状态：当前实现说明
> 适用版本：1.10.0
> 更新日期：2026-10-15
> 配置依据：`compose.yml`、`compose.nano.yml`、`.env.example`

本文记录当前仓库已经实现的容器、网络、端口、持久化和容量边界。规划中的微服务、多节点集群或
尚未进入 `compose.yml` 的组件不在当前部署清单中。

## 1. 部署原则

- 单机部署统一使用 Docker Engine 和 Docker Compose v2。
- 开发机和普通 Linux 主机使用 `compose.yml`；Nano 叠加 `compose.nano.yml`。
- 核心服务默认启动；TURN 和监控通过 Compose profile 按需启用。
- 环境差异通过 `.env` 和 Compose override 表达，镜像内不写死现场 IP 或密钥。
- MySQL、Redis、MinIO、EMQX 和应用日志使用命名卷持久化。
- 普通停机不得使用 `docker compose down -v`。
- Nano 使用包含全部镜像的离线包，不在目标设备执行源码构建或 `docker pull`。

## 2. 当前容器清单

### 2.1 核心业务和基础服务

| Compose 服务 | 镜像 | 作用 | 运行形态 |
| --- | --- | --- | --- |
| `api` | `yoox/cloud-gcs-api:${YOOX_VERSION}` | HTTP API、WebSocket、MQTT 适配、控制、航线和媒体业务 | 常驻 |
| `web` | `yoox/cloud-gcs-web:${YOOX_VERSION}` | Vue 管理台及 Pilot/Web 反向代理 | 常驻 |
| `api-portal` | `yoox/cloud-gcs-api-portal:${YOOX_VERSION}` | 离线开发文档站 | 常驻 |
| `mysql` | `mysql:8.4.6` | 业务持久化 | 常驻 |
| `mysql-init` | `mysql:8.4.6` | 初始化账号 MQTT 字段 | 一次性 |
| `redis` | `redis:7.4.9-alpine` | 在线态、缓存、控制状态和 MQTT ACL | 常驻 |
| `minio` | `minio/minio:RELEASE.2025-04-22T22-12-26Z` | 航线和媒体对象存储 | 常驻 |
| `minio-init` | `minio/mc:RELEASE.2025-04-16T18-13-26Z` | 幂等创建 Bucket | 一次性 |
| `emqx` | `emqx/emqx:5.8.9` | 设备 MQTT 和浏览器 DRC MQTT WebSocket | 常驻 |
| `emqx-init` | `curlimages/curl:8.15.0` | 幂等创建 MQTT 用户 | 一次性 |
| `mediamtx` | `yoox/mediamtx:1.19.3` | RTSP 入流和 WebRTC/WHEP 播放 | 常驻 |

设备适配、航线任务、媒体控制等逻辑目前位于 `api` 模块化单体中，并没有独立的
`device-adapter`、`worker` 或数据库迁移容器。

### 2.2 可选 profile

| Profile | 服务 | 默认状态 |
| --- | --- | --- |
| `turn` | `coturn` | 不启动 |
| `monitoring` | Prometheus、Grafana、Loki、Promtail、cAdvisor、Node Exporter | 不启动 |

完整 Nano 离线包包含这些可选镜像，但安装时仍按 profile 决定是否运行。

## 3. 当前工程结构

```text
compose.yml                         # 主 Compose
compose.nano.yml                    # Nano 资源限制覆盖层
.env.example                        # 安全占位配置
deploy/

├── mediamtx/                       # 流媒体配置和镜像扩展
├── prometheus/
├── grafana/
├── loki/
├── promtail/
└── systemd/                        # RTSP 辅助服务样例
scripts/
├── preflight.sh
├── smoke-test.sh
├── sync-offline.sh

offline/nano-deploy/                # Nano 离线部署模板
```

不存在 `deploy/compose/compose.media.yaml` 等拆分文件。文档和自动化只能引用上述实际路径。

## 4. 网络和端口

### 4.1 对外端口

| 默认端口 | 协议 | 用途 | 配置项 |
| ---: | --- | --- | --- |
| 8080 | TCP | Web 控制台、HTTP API、WHEP 反向代理 | `YOOX_HTTP_PORT` |
| 9000 | TCP | Pilot 登录、平台 WebSocket、DRC MQTT WebSocket | `YOOX_PILOT_PORT` |
| 8081 | TCP | API Portal | `YOOX_API_PORTAL_PORT` |
| 1883 | TCP | 设备 MQTT | `YOOX_MQTT_PORT` |
| 8554 | TCP | RTSP 控制和 TCP 交织传输 | `YOOX_PUBLIC_RTSP_PORT` |
| 8188 | UDP | RTSP RTP | `YOOX_RTP_PORT` |
| 8189 | UDP | RTSP RTCP | `YOOX_RTCP_PORT` |
| 8000 | UDP/TCP | WebRTC ICE | `YOOX_WEBRTC_ICE_PORT` |
| 9100 | TCP | MinIO S3 API，供设备下载航线和上传媒体 | `YOOX_MINIO_S3_PORT` |

RTSP 默认允许 `udp,tcp`。macOS Docker Desktop 的 RTSP 入流建议强制 TCP；Linux/Nano 保持
`udp,tcp`。WebRTC ICE 独立开放 UDP 和 TCP 8000。

### 4.2 本机管理端口

以下端口在 Compose 中只绑定 `127.0.0.1`：

| 端口 | 服务 |
| ---: | --- |
| 19000 | API Actuator/诊断 |
| 9001 | MinIO Console |
| 18083 | EMQX Dashboard |
| 3000 | Grafana |
| 9090 | Prometheus |
| 3100 | Loki |
| 8088 | cAdvisor |
| 9101 | Node Exporter；容器内仍监听 9100，避免与 MinIO S3 冲突 |

### 4.3 网络边界

- 所有容器加入 `${COMPOSE_PROJECT_NAME}-net`。
- MySQL、Redis 不发布宿主机端口。
- API 业务端口只供 Compose 网络和 Web 反向代理使用，诊断端口仅绑定本机。
- 公网部署应在上游增加 TLS/VPN 和来源限制；当前 Compose 不直接提供完整公网 TLS 终止。
- 双网卡部署应分别设置 RTSP、MinIO、WebRTC 和 DRC 对外地址，详见配置指南。

| 命名卷 | 数据 |
| --- | --- |
| `mysql-data` | 数据库 |
| `redis-data` | Redis AOF |
| `minio-data` | 航线和媒体对象 |

## 6. 部署形态

### 6.1 macOS 开发

```bash
make init
make verify
make up
make smoke
```

`.env` 中应设置 `YOOX_RTSP_TRANSPORTS=tcp`。监控容器看到的是 Docker Desktop Linux VM，
不能等同于 macOS 主机指标。

### 6.2 Linux 单机

```bash
make init
make verify
make up
make smoke
```

设备跨主机访问时开放第 4.1 节所需端口，并将 `YOOX_PUBLIC_HOST` 设置为设备可达地址。

### 6.3 Nano 8GB B 版

Nano 使用完全离线包和 `compose.nano.yml`，不克隆仓库、不拉取镜像、不执行 Maven/npm 构建。
详细步骤见 [Nano 完全离线快速部署](13-Nano快速部署.md)。

## 7. Nano 资源预算

`compose.nano.yml` 的核心常驻服务上限如下：

| 服务 | 内存上限 | CPU 上限 |
| --- | ---: | ---: |
| MySQL | 480 MB | 0.4 核 |
| Redis | 96 MB | 0.2 核 |
| MinIO | 256 MB | 0.3 核 |
| EMQX | 512 MB | 0.4 核 |
| MediaMTX | 128 MB | 0.3 核 |
| API | 900 MB | 1.0 核 |
| Web | 64 MB | 0.1 核 |
| API Portal | 48 MB | 0.1 核 |
| **常驻合计** | **约 2.5 GB** | **2.8 核** |

初始化容器只短暂运行。监控和 TURN 没有纳入上述常驻预算；与 YOLOv5 共存时应按实际负载决定
是否启用监控。

## 8. 容量估算

### 8.1 视频

```text
设备上行带宽 = 并发推流路数 × 单路码率 × 1.2
媒体出口带宽 = Σ(单路码率 × 同时观看人数) × 1.2
录制日存储 = 单路码率(Mbps) × 10.8 GB × 每日小时数
```

示例：20 路、平均 4 Mbps、每路 2 个观看者，设备总上行约 96 Mbps，媒体出口约
192 Mbps。当前 MediaMTX 主要转封装而非转码；引入转码后必须单独评估 CPU/GPU。

### 8.2 遥测

100 台设备、每台 0.5 Hz、单条 3 KB 时，原始数据约 150 KB/s、12.96 GB/天。当前实现主要在
Redis 保存最新在线态和 OSD；长期轨迹与原始事件需要另行制定保留策略，不能直接套用该理论值。

### 8.3 对象存储

MinIO 容量取决于 KMZ、媒体和日志保留期。部署前应明确：

- 单设备每日照片/视频量；
- 媒体保留期和删除策略；
- 数据盘容量、扩容方式和备份目标；
- 设备到 MinIO 外部地址的带宽和可达性。

## 9. 可观测性

启用 `monitoring` profile 后采集：

- API Actuator 指标；
- MediaMTX 指标；
- 容器 CPU、内存、网络和重启；
- 主机资源；
- 容器日志。

监控组件当前只提供本机入口，不包含 Alertmanager。远程访问应使用 SSH 隧道、VPN 或带认证的
反向代理。

## 10. 备份和恢复

- MySQL 使用一致性逻辑备份，不能只复制正在运行的数据目录。
- MinIO 使用 `mc mirror` 或对象存储复制到独立介质。
- Redis AOF 不是业务主数据的唯一备份；短时 DRC 状态不应跨灾难恢复继续使用。
- 加密保存 `.env`、版本号、Compose 配置和镜像归档。
- 至少定期验证一次从空主机和离线包恢复。

## 11. 升级和回滚

普通主机按固定版本镜像升级；Nano 使用新离线包的 `install.sh --update`。升级前必须确认无活跃
DRC、点飞、返航、降落或航线任务，并备份数据。回滚要求镜像、Compose 和数据库结构兼容。

## 12. 部署验收

- Compose 配置可以解析，所有核心镜像版本固定。
- 常驻核心容器为 `running/healthy`，三个 init 容器成功退出。
- `scripts/smoke-test.sh` 通过。
- Pilot、MQTT、RTSP、WebRTC、MinIO 外部地址在目标网络可达。
- MySQL、Redis 和管理端口未直接暴露公网。
- 资源使用、磁盘余量和日志轮转满足现场负载。
- 备份、更新和回滚步骤经过演练。
