# 全国离线地图与高德切换

## 使用方式

私有化部署默认加载全国普通离线地图。首页和虚拟座舱的“地图来源”下拉框可切换到高德在线地图。
高德仍支持普通图、卫星图切换，需要操作电脑能访问高德服务及有效 Key。
离线模式不请求高德脚本、在线字体、在线图标或其他公网地图资源。

地图来源选择在本次页面导航期间保留，完整刷新后重新使用部署默认值，避免上次选择高德导致
断网现场首次打开失败。高德加载失败后可切换回离线地图。

两种地图保留飞机、遥控器、航向、轨迹、定位跟随、测距目标、指点飞行及云台 Look At 选点。
业务状态、轨迹和指令参数始终使用 WGS84，只有高德适配器内部转换 GCJ-02。
切换地图不下发飞行指令，不清除正在执行的任务目标。

## 配置与架构

```dotenv
YOOX_MAP_PROVIDER=offline
YOOX_MAP_DATA_DIR=./maps
```

地图目录只读挂载到 Web 容器 `/srv/maps`，通过现有 8080 端口的 `/maps/` 提供。
PMTiles 使用 HTTP Range 请求，成功响应为 206；地图数据不经过 Java API。
MapLibre JS/CSS/Worker 随 Web 镜像提供，字体、图标和样式随地图包提供。
完整 Noto CJK 字体在初始化地图前从本地加载，因此不依赖操作电脑预装中文字体。

开发环境运行 `npm run dev` 时，`/maps/` 代理到本机 8080 的 Web 容器。

## 在联网构建机准备全国包

前置条件：Node.js、Python 3、已安装的 `web-console` npm 依赖、curl、unzip、go-pmtiles v1.31.2。
目标 Nano 不需要这些构建工具，也不需要联网。

```bash
cd web-console
npm ci
cd ..
PMTILES_BIN=/path/to/pmtiles make offline-map
```

脚本 `scripts/prepare-offline-map.sh` 固定上游地图、字体和图标版本，
按 `deploy/maps/china-coverage.geojson` 提取全国 0–15 级数据。
范围文件是瓦片提取范围，不能作为行政边界使用；包含额外海域及港澳覆盖。
底图界线、地名和细节来自上游数据，需要按交付地点检查。
界面允许放大到 20 级，16–20 级为已有 15 级数据放大，不会增加原始地图细节。

可显式指定 `YOOX_MAP_SOURCE`、`YOOX_MAP_VERSION` 和 `YOOX_MAP_DATA_DIR`。
构建时保留完整 Range 缓存与已接收前缀的检查点，网络中断后可继续读取，提取成功后自动清理缓存。
同机提取时应预留“地图本体＋完整下载缓存”的空间；该缓存不会进入离线交付包。
下载器使用 HTTP/1.1，支持超过 512 MiB 的单次范围请求，并校验上游范围及文件标识。
跨机器提取遇到不稳定的 SSH 链路时，可在提取端运行 `scripts/map-range-relay.py`，
将 `--source` 指向 SSH 转发的本地地址。转发器保留当前响应已写入的位置，
默认等待链路恢复最多 15 分钟；重试原始范围并跳过已交付前缀，复用构建机缓存。
它只用于构建，正式部署和地图访问不依赖 SSH 或该转发器。
更换源必须保持 Protomaps v4 数据结构，地图包与样式不能任意混用。
已发布版本不可覆盖；更新必须使用新版本号。

准备流程验证北京、上海、广州、成都、乌鲁木齐、拉萨、哈尔滨、海口、香港、澳门、台北
的 6、10、15 级瓦片，并为全部资源生成 SHA-256。地图署名和字体、图标许可随包提供。
实际文件大小和上游来源记录在 `manifest.json`，不得将原始 OSM 大小当成交付包大小。

## 离线包结构

```text
maps/
  current.json
  releases/<version>/
    china.pmtiles
    style.json
    fonts/                 # 完整 CJK OTF、其他文字 PBF、字体许可
    sprites/               # 普通屏和高分屏图标、图标许可
    manifest.json
    coverage.geojson
    SHA256SUMS
    NOTICE.txt
```

`scripts/build-nano-offline-bundle.sh` 必须找到并验证全国地图包才会构建交付包。
可用 `--map-dir` 指定目录。最终单文件离线包包含业务镜像、地图、中文字体、图标和安装脚本。
地图不存入 Git，也不写入 Web 镜像；更新应用与更新地图可以分开进行。

```bash
bash scripts/build-nano-offline-bundle.sh --version nano-<version> --map-dir ./maps
```

构建机不便保留额外完整归档时可使用 `--stream`：归档写入 stdout，进度写入 stderr，
可通过 SSH 管道直接保存到交付机器。管道必须开启 `pipefail`，先保存为 `.partial`，
确认构建成功并通过 gzip 完整性检查后再改为最终文件名和生成 SHA-256。
如已在联网构建机完成镜像构建并将全部镜像导入 Nano，可在 Nano 上使用 `--skip-build` 组装。
此模式不会构建或拉取镜像，缺少任一镜像即退出，仍执行地图完整性和镜像架构校验。

离线 `install.sh` 在加载镜像前校验地图，启动前将地图安装到 `.env` 指定的目录，
更新时保留已有 `.env` 和数据卷。第一次完整安装不依赖浏览器缓存。
磁盘应容纳当前包、新包和解包临时空间；复制前脚本检查空间。
地图文件和完整归档可能超过 4 GiB，传输介质应使用支持大文件的 exFAT、NTFS 或 Linux 文件系统，
不要将单文件归档直接复制到 FAT32 U 盘。

## 单独更新及回滚地图

将新的完整 `maps` 目录传入现场后运行：

```bash
bash scripts/install-offline-map.sh /path/to/new/maps /path/to/deployment/maps
```

安装先核对全部文件哈希，再原子替换 `current.json`。旧版本目录保留，
已打开的地图继续请求旧版本资源；刷新后使用新版本。
回滚时恢复旧的 `current.json`，刷新页面即可。不要在有客户端仍使用旧版本时删除其目录。
应用容器重建不会删除地图数据。

## 验证

```bash
make verify
cd web-console
npm test
cd ..
make up
make smoke
bash scripts/smoke-map.sh http://192.168.88.197:8080
```

浏览器测试命令为 `cd web-console && YOOX_MAP_TEST_URL=http://<部署IP>:8080 npm run test:map-browser`。
默认两项测试阻断外网并模拟设备接口和 WebSocket；设置 `YOOX_MAP_TEST_AMAP=1` 可额外验证
真实高德在线图层。Chrome 路径可通过 `YOOX_CHROME_PATH` 指定。
下载器边界回归：`python3 scripts/test-map-range-cache.py`，覆盖大范围、4 GiB 以上偏移及检查点恢复。
断连续传回归：`python3 scripts/test-map-range-relay.py`，验证上游中断后不会重复或丢失响应字节。

地图 smoke 验证 PMTiles 的 206 响应、文件头、样式、PBF、中文字体、两种分辨率图标，
并确认缺失文件返回 404，而不是 SPA 的 HTML。超过 4 GiB 的地图包还会校验 4 GiB 偏移处
的实际响应字节与构建时 SHA-256 一致，覆盖大文件 Range 读取。

构建校验核对全国代表地点的实际瓦片；浏览器回归使用全新上下文并阻断站外请求，
核对中文渲染、地图切换及座舱状态。
自动化模拟地图点击与设备遥测，不向真实飞行器发送控制指令。实机飞行安全验证须在受控现场进行。

全国地址搜索、地址反查、道路导航和卫星影像不属于该普通离线底图包。
