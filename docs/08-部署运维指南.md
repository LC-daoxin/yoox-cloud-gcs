# YOOX Cloud GCS 部署与运维指南

## 1. 部署前检查

- Linux x86_64/arm64 主机，Docker Engine 24+，Compose v2。
- 核心栈建议 4 核、8 GB 内存、30 GB 系统盘；媒体和对象存储使用独立数据盘。
- 主机时间同步，时区明确，DNS 和证书可用。
- 设备网络可达 Pilot 网关 9000、MQTT 1883、RTSP 8554；浏览器可达 Web 入口和 WebRTC UDP 8189。
- `.env` 已替换所有示例 Secret，`YOOX_PUBLIC_HOST` 不是回环地址。
- 已取得上云应用 ID、Key、License 和对应设备/固件授权。

执行：

```bash
cp .env.example .env
docker compose --env-file .env config --quiet
docker compose --env-file .env pull
docker compose --env-file .env build
docker compose --env-file .env up -d --wait --wait-timeout 300
```

## 2. 启动验收

```bash
docker compose --env-file .env ps
docker compose --env-file .env logs --tail=200 api
curl -fsS http://127.0.0.1:8080/healthz
curl -fsS http://127.0.0.1:8080/actuator/health
curl -sS http://127.0.0.1:9000/manage/api/v1/login
curl -fsS http://127.0.0.1:8081/healthz   # 在线 API 文档门户
```

验收顺序：

1. 所有核心容器为 `running/healthy`，两个 init 容器为成功退出。
2. Web 登录，默认工作空间正确。
3. Pilot/设备登录并连接 MQTT，设备拓扑出现。
4. OSD、state、HMS 持续更新。
5. 选择 `live_capacity` 中的视频源，启动 RTSP，浏览器出现首帧。
6. 在授权测试条件下进入 DRC，验证排他控制、心跳、零杆、返航、退出和断网收敛。
7. 上传 KMZ、创建任务、跟踪进度并检查媒体回传。

## 3. 运维命令

```bash
docker compose --env-file .env ps
docker compose --env-file .env logs -f --tail=200
docker compose --env-file .env restart api
docker compose --env-file .env up -d --build api web
docker compose --env-file .env --profile monitoring up -d
```

不要用 `docker compose down -v` 做普通停机；`-v` 会删除命名卷中的数据库、对象和监控数据。

## 4. 监控入口

启用 `monitoring` profile 后：

| 组件 | 本机地址 | 说明 |
| --- | --- | --- |
| Grafana | `127.0.0.1:3000` | YOOX 概览、指标和日志 |
| Prometheus | `127.0.0.1:9090` | API、媒体、容器、主机指标 |
| Loki | `127.0.0.1:3100` | 日志 API |
| cAdvisor | `127.0.0.1:8088` | 容器资源 |
| Node Exporter | `127.0.0.1:9100` | 主机资源 |
| EMQX Dashboard | `127.0.0.1:18083` | MQTT 连接和流量 |
| MinIO Console | `127.0.0.1:9001` | 对象存储 |

这些地址默认只允许主机访问。远程维护建议用 VPN 或 SSH 隧道：

```bash
ssh -L 3000:127.0.0.1:3000 -L 18083:127.0.0.1:18083 user@server
```

后期 YOOX Ops Console 应调用 Docker 只读 Agent、Actuator、Prometheus、Loki、EMQX 与
MediaMTX API，统一展示容器状态、依赖健康、媒体会话、设备连接、容量和告警。写操作必须经过
独立 RBAC、审批和审计，不能把 Docker Socket 直接暴露给 Web。

## 5. 备份与恢复

备份前记录镜像版本和 `.env` 的安全副本。数据库使用逻辑备份：

```bash
docker compose --env-file .env exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot cloud_sample --single-transaction --routines --events' \
  > yoox-cloud-sample.sql
```

实际执行时密码应通过安全方式提供，避免写入 shell 历史。Redis 使用 AOF 卷，MinIO 使用
`mc mirror` 同步到独立存储。仅备份 Docker 卷目录不足以保证 MySQL 一致性。

恢复必须先在隔离环境验证。恢复顺序：MySQL → Redis（如需保留短时状态）→ MinIO → API →
Web；DRC 临时租约和短时令牌不应跨灾难恢复继续使用。

## 6. 升级和回滚

1. 备份数据库和对象存储。
2. 拉取固定版本镜像，执行 `docker compose config --quiet`。
3. 在测试环境运行 API、RTSP、DRC 和航线回归。
4. 滚动替换无状态 Web/API；涉及数据库变更时按迁移说明执行。
5. 观察错误率、MQTT 断线、直播首帧、DRC 延迟和容器重启。

回滚只允许回到与数据库 Schema 兼容的版本。生产镜像不得使用 `latest`。

## 7. 故障定位

| 症状 | 首要检查 |
| --- | --- |
| Web 502 | `api` 健康、Nginx 日志、MySQL/Redis |
| 设备不上线 | 公网 1883、EMQX 用户、应用 License、Topic ACL |
| 有设备无视频源 | `live_capacity`、相机/负载能力、固件 |
| RTSP 已推无画面 | MediaMTX publisher、WHEP 请求、H.264、UDP 8189/TURN |
| DRC 连接拒绝 | 设备在空、控制权、任务状态、JWT Secret、Redis ACL |
| 航线失败 | KMZ/WPML、设备型号、负载、返航高度、电量、时间同步 |
| 媒体无回传 | STS、MinIO endpoint、Bucket、设备到对象存储网络 |

## 8. 安全基线

- 上线前修改 Web 初始化密码和所有 `.env` Secret。
- 使用 TLS/WSS，限制 MQTT/RTSP 源 IP，管理端口不出公网。
- 每次远控前完成安全检查单，设置控制租约、心跳超时和现场接管方案。
- 不在日志中记录 JWT、MQTT 密码、MinIO 签名 URL 或完整上云凭据。
- 定期做依赖、镜像、配置和弱口令扫描。
- 真机飞行必须遵守当地法规、空域授权和组织安全流程。

- Web 初始化账号 `admin / Yoox@123456` 仅用于首次登录，投产前必须修改。
- 生产环境应在上游配置 TLS/WSS，并按最小化原则收敛安全组开放范围。
