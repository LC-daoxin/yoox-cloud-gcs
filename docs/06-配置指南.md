# YOOX Cloud GCS 配置指南

> 适用版本：1.10.0
> 更新日期：2026-10-15
> 配置源：`.env.example`、`compose.yml`、`cloud-service/src/main/resources/application.yml`

## 1. 首次配置

```bash
cd /path/to/YOOX_Cloud_GCS
cp .env.example .env
chmod 600 .env
```

将 `.env` 中所有包含 `change_me` 或 `replace_with` 的值替换。Secret 建议由密码管理器生成，
至少 32 个随机字符。`.env` 不应提交到版本库。

最关键的地址是 `YOOX_PUBLIC_HOST`。它必须是浏览器和无人机/机巢都能访问的服务器 IP 或
DNS 名称。远端设备接入时不能配置为 `127.0.0.1`、`localhost` 或 Docker 服务名。

## 2. 配置项

### 2.1 项目与运行时

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `COMPOSE_PROJECT_NAME` | `yoox-cloud-gcs` | Compose 项目名及网络/数据卷前缀；迁移时不得随意修改 |
| `TZ` | `Asia/Shanghai` | 容器时区 |
| `YOOX_LOG_LEVEL` | `INFO` | `com.yoox` 应用日志级别 |
| `YOOX_JAVA_OPTS` | 容器友好 JVM 参数 | API JVM 参数；Nano 由 `compose.nano.yml` 覆盖堆和 GC |

### 2.2 公开地址与端口

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `YOOX_PUBLIC_HOST` | `127.0.0.1` | 返回给设备和浏览器的公共主机名 |
| `YOOX_HTTP_PORT` | `8080` | Web 控制台、HTTP API、WHEP 的浏览器入口 |
| `YOOX_PILOT_PORT` | `9000` | 遥控器登录、平台 WebSocket、DRC MQTT WebSocket 公网入口 |
| `YOOX_API_PORTAL_PORT` | `8081` | 在线 API 文档门户（`api-portal` 静态站）入口 |
| `YOOX_API_DIAGNOSTIC_PORT` | `19000` | API 本机诊断端口，仅绑定 `127.0.0.1` |
| `YOOX_PUBLIC_RTSP_PORT` | `8554` | 设备 RTSP 推流端口 |
| `YOOX_RTSP_TRANSPORTS` | `udp,tcp` | MediaMTX 允许的 RTSP 传输；macOS Docker Desktop 建议设为 `tcp` |
| `YOOX_RTP_PORT` | `8188` | RTSP 使用 UDP 时的 RTP 端口 |
| `YOOX_RTCP_PORT` | `8189` | RTSP 使用 UDP 时的 RTCP 端口 |
| `YOOX_WEBRTC_ICE_PORT` | `8000` | WebRTC ICE 媒体端口，Compose 同时开放 UDP 和 TCP 回退 |
| `YOOX_MINIO_S3_PORT` | `9100` | 设备下载 KMZ、上传媒体所用的 MinIO S3 外部端口 |
| `YOOX_MQTT_PORT` | `1883` | 设备 MQTT/TCP 端口 |
| `YOOX_MQTT_ADVERTISED_FOLLOW_REQUEST_HOST` | `true` | 登录返回的 `mqtt_addr` 按客户端本次访问的主机名下发（多网段部署必需） |
| `YOOX_PUBLIC_RTSP_HOST` | 继承 `YOOX_PUBLIC_HOST` | 设备 RTSP 推流目标，双网卡时应使用设备所在网段的地址 |
| `YOOX_MINIO_EXTERNAL_ENDPOINT` | 按 `YOOX_PUBLIC_HOST` 生成 | 设备上传/下载文件的 MinIO 外部地址 |
| `YOOX_WEBRTC_ADDITIONAL_HOSTS` | 继承 `YOOX_PUBLIC_HOST` | MediaMTX 对浏览器公布的 ICE 地址；多个地址用逗号分隔 |
| `YOOX_DRC_MQTT_HOST` | 继承 `YOOX_PUBLIC_HOST` | 浏览器 DRC MQTT over WebSocket 目标主机 |
| `YOOX_RTSP_USERNAME` | `yoox-publisher` | 设备发布 RTSP 时使用的专用账号 |
| `YOOX_RTSP_PASSWORD` | 无安全默认值 | RTSP 发布密码，必须更换占位符 |

公有云安全组至少按需开放 TCP `8080/9000/8554/1883/8000/9100`，以及 UDP
`8000/8188/8189`；如需对外提供在线 API 文档门户，另开放 TCP `8081`。公网生产环境应在上游
负载均衡或反向代理配置 TLS，将 Web 与 MQTT WebSocket 升级为 HTTPS/WSS。管理端口
`19000/9001/18083/3000/9090/3100/8088/9101` 默认只绑定本机，不应直接暴露公网。

遥控器云服务参数默认填写：

```text
登录地址  http://<YOOX_PUBLIC_HOST>:9000
WebSocket ws://<YOOX_PUBLIC_HOST>:9000/api/v1/ws
```

#### 多网段部署（遥控器与总控端不在同一网段）

当服务器双网卡接入（例如遥控器直连 `192.168.2.0/24`、总控端经交换机在
`192.168.3.0/24`）时，`YOOX_PUBLIC_HOST` 只能填一个网段的地址。登录、WebSocket 和
驾驶舱拉流都按浏览器当前地址相对访问，不受影响；但登录接口返回的 `mqtt_addr`
是绝对地址，客户端直接拿它连 Broker 时就会指向另一个不可达的网段。

`YOOX_MQTT_ADVERTISED_FOLLOW_REQUEST_HOST=true`（默认）会把 `mqtt_addr` 的主机名换成
客户端本次登录所用的主机名（协议与端口仍取 `YOOX_MQTT_ADVERTISED_ADDRESS`）：遥控器
从 `192.168.2.x:9000` 登录得到 `tcp://192.168.2.x:1883`，总控端从 `192.168.3.x:9000`
登录得到 `tcp://192.168.3.x:1883`。客户端通过回退地址或反代域名接入时仍使用配置值。

仍需注意：`YOOX_PUBLIC_RTSP_HOST` 与 MinIO 外部端点是下发给**设备**的地址，必须保持
遥控器所在网段；若总控端也需直接下载航线 KMZ/媒体，则需在两个网段间打通路由。
MediaMTX 的 `YOOX_WEBRTC_ADDITIONAL_HOSTS` 应同时包含浏览器可达的 Wi-Fi 地址和设备直连地址，
例如 `192.168.88.197,192.168.5.2`。

### 2.3 数据和认证

| 配置项 | 是否敏感 | 说明 |
| --- | --- | --- |
| `YOOX_DB_NAME` | 否 | MySQL 数据库，默认 `cloud_sample` |
| `YOOX_DB_USER` | 否 | API 数据库用户 |
| `YOOX_DB_PASSWORD` | 是 | API 数据库密码 |
| `YOOX_DB_ROOT_PASSWORD` | 是 | 初始化和维护用 MySQL root 密码 |
| `YOOX_REDIS_PASSWORD` | 是 | Redis 密码，同时供 EMQX ACL 数据源读取 |
| `YOOX_JWT_SECRET` | 是 | Web API 令牌和 DRC MQTT 短时令牌签名密钥 |

修改 JWT Secret 会使既有 Web 与 DRC 会话立即失效。Redis 密码变更必须同步重建 Redis、API
和依赖 Redis 的服务。已有数据卷的 MySQL 用户密码不能只通过修改 `.env` 完成：
`MYSQL_PASSWORD` 和 `MYSQL_ROOT_PASSWORD` 只在首次初始化数据目录时生效。轮换 MySQL 密码时，
必须先在数据库中执行密码变更，再同步修改 `.env` 并重建所有数据库客户端；操作前应完成逻辑备份。

### 2.4 MQTT

| 配置项 | 说明 |
| --- | --- |
| `YOOX_MQTT_USERNAME` | 后端服务消费和发布设备消息的账号名，当前 ACL 要求 `yoox-cloud` |
| `YOOX_MQTT_PASSWORD` | 后端服务 MQTT 密码 |
| `YOOX_DEVICE_MQTT_USERNAME` | Pilot/设备登录后获得的 MQTT 账号名，当前初始化值为 `pilot` |
| `YOOX_DEVICE_MQTT_PASSWORD` | Pilot/设备 MQTT 密码；当前初始化流程要求与 Pilot 配置一致 |
| `YOOX_DEVICE_AUTO_REGISTER_ENABLED` | 是否在首次收到设备拓扑时自动注册并绑定，默认 `true` |
| `YOOX_DEVICE_AUTO_REGISTER_WORKSPACE_ID` | 自动注册设备所属的工作空间 ID；多工作空间部署必须显式设置 |
| `YOOX_EMQX_DASHBOARD_PASSWORD` | EMQX 管理员密码 |

`emqx-init` 会幂等创建/更新服务账号与设备账号；`mysql-init` 同步设备 MQTT 凭据到初始化用户。
设备连接 MQTT/TCP 时使用设备账号。浏览器 DRC 不使用长期设备密码，而是由 API 签发短时 JWT，
权限从 Redis 的 `mqtt_acl:<client-id>` 哈希读取。

启用自动注册后，平台优先保留设备已有的工作空间归属；只有未绑定设备才使用
`YOOX_DEVICE_AUTO_REGISTER_WORKSPACE_ID`。已分别绑定到不同工作空间的遥控器和飞机不会被
自动迁移或合并。


### 2.6 对象存储

| 配置项 | 说明 |
| --- | --- |
| `YOOX_MINIO_ACCESS_KEY` | MinIO 管理/应用访问键 |
| `YOOX_MINIO_SECRET_KEY` | MinIO Secret |
| `YOOX_MINIO_BUCKET` | 航线和媒体桶，初始化任务自动创建 |

默认 endpoint 是容器内地址 `http://minio:9000`。如果改用 S3 兼容服务，需要同时确认设备直传
所需的签名地址能被设备网络访问。

### 2.7 TURN 与监控

TURN 通过 `turn` profile 启动；配置 `YOOX_TURN_REALM`、`YOOX_TURN_USERNAME`、
`YOOX_TURN_PASSWORD` 和 `YOOX_TURN_PORT`。同时需要把 TURN URL 写入
`deploy/mediamtx/mediamtx.yml` 的 WebRTC ICE Server 配置后重建 MediaMTX。

`monitoring` profile 使用 `YOOX_GRAFANA_ADMIN_PASSWORD` 初始化 Grafana。监控端口均为本机
端口，建议通过 SSH 隧道或带认证的反向代理访问。

## 3. RTSP 媒体配置

当前平台只启用 RTSP 设备入流：

```text
设备 --RTSP publish--> YOOX MediaMTX :8554
浏览器 <--WebRTC/WHEP-- Web :8080/webrtc/<stream>/whep
```

API 根据视频源生成流标识，并向设备下发：

```text
rtsp://<YOOX_PUBLIC_HOST>:<YOOX_PUBLIC_RTSP_PORT>/<stream-id>
```

实际下发地址包含 `YOOX_RTSP_USERNAME/PASSWORD`。密码应使用 URL 安全字符；若包含 `@`、`:`、
`/` 等保留字符，必须先做百分号编码。

MediaMTX 配置中 `rtmp`、`hls`、`srt`、`moq` 均关闭。上云 API 后期能力矩阵中的 RTMP 和
GB28181 不在 P0 端口、容器、前端入口和验收范围中。

跨网访问时的排查顺序：

1. 从设备所在网络测试服务器 TCP 8554 可达。
2. 在 MediaMTX 日志确认 publisher 已连接并创建路径。
3. 从浏览器网络检查 WHEP POST 是否返回 `201 Created`。
4. 若 WHEP 成功但 MediaMTX 日志出现 `deadline exceeded while waiting connection`，
   检查浏览器到 `YOOX_PUBLIC_HOST:8000` 的 UDP/TCP 可达性，以及 Compose 是否同时映射
   `8000/udp` 和 `8000/tcp`。macOS/Docker Desktop 必须保留 TCP ICE 回退。
5. 确认设备编码为浏览器兼容的 H.264；不兼容编码需要新增转码服务。

MediaMTX 启用 `overridePublisher` 仅允许同一流名的新、已鉴权 publisher 原子替换旧会话。
这用于清理设备网络切换或媒体服务重启后遗留的 0 RTP 会话；后端在已有有效媒体包时
直接复用 publisher，并对刚受理的启动指令做 30 秒去重，避免多页面重复下发。

## 4. 公有云与私有化

公有云建议使用 DNS、TLS 证书、独立数据盘和安全组白名单；云数据库或对象存储替换需要单独
验证兼容性。普通私有化主机使用同一 `compose.yml`，将公共地址换为客户局域网地址。

Nano 完全离线部署不要手工挑选镜像。使用 `scripts/build-nano-offline-bundle.sh` 生成包含
全部 17 个 arm64 镜像、全国普通地图、中文字体、图标、Compose、SQL、配置和校验文件的单一归档，目标 Nano 不执行
`docker pull`。详见 [Nano 完全离线快速部署](13-Nano快速部署.md)。

地图默认 `YOOX_MAP_PROVIDER=offline`，数据目录为 `YOOX_MAP_DATA_DIR=./maps`。
首页和座舱可以切换高德在线地图；高德仍使用现有运行时 Key 配置。
地图包制作和升级见 [全国离线地图与高德切换](20-全国离线地图与高德切换.md)。

## 5. 配置验证

源码部署：

```bash
docker compose --env-file .env config --quiet
docker compose --env-file .env up -d --build --wait --wait-timeout 300
docker compose --env-file .env ps
curl -fsS http://127.0.0.1:19000/actuator/health
```

Nano 已部署实例：

```bash
cd /home/jetson/yoox-cloud-gcs
docker compose --env-file .env -f compose.yml -f compose.nano.yml config --quiet
docker compose --env-file .env -f compose.yml -f compose.nano.yml up -d --wait --wait-timeout 300
docker compose --env-file .env -f compose.yml -f compose.nano.yml ps --all
curl -fsS http://127.0.0.1:19000/actuator/health
```

修改 `.env` 后不能只执行 `docker compose restart`，因为它不会重新加载容器环境变量。完整的备份、
安全检查、应用配置和回滚流程见 [部署与运维指南](08-部署运维指南.md)。

## 可选 RTSP 低码率转码

x86 Linux 可显式叠加 `compose.transcode.yml`，使用独立 FFmpeg 容器发布 `-low` 流。
默认最高 720p、25 fps、目标 1500 kbps，限制 2 核 CPU / 768 MB 内存，不新增端口或卷。
输入路径及 `YOOX_TRANSCODE_*` 参数见 [RTSP 低码率转码服务](21-RTSP低码率转码服务.md)。
该服务默认不启动，使用现有 RTSP 发布凭据，未纳入现有离线镜像包。

## 可选 RTSP 时间戳修正

宿主机 `yoox-rtsp-normalizer` 使用 `/etc/default/yoox-rtsp-normalizer` 配置
`YOOX_RTSP_NORMALIZER_SOURCE_PATH` 和 `YOOX_RTSP_NORMALIZER_TIMESTAMP_MODE`。
模式默认 `wallclock`；`rtp-microseconds` 仅适用于已确认的微秒/90 kHz 单位错误。
发布凭据仍从原 `.env` 读取。部署、验收与回滚见
[RTSP 时间戳异常定位与服务端修正](23-RTSP时间戳异常定位与服务端修正.md)。
