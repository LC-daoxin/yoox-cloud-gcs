# YOOX Cloud GCS 实施计划与验收标准

## 1. 计划假设

本计划以以下首期基线估算：

- 18 周完成可生产试点版本。
- 100 台在线设备、20 路并发直播、5 路并发远程控制。
- 首批至少包含 EVO Max 4T + Smart Controller V3；机巢能力以实际设备到位为准。
- 地图、对象存储和 MQTT 基础环境能在第 2 周前就绪。
- 团队具备正式的远程飞行测试场地、飞手和现场安全员。

范围或硬件晚于计划确认会直接影响虚拟座舱、机巢调试和航线任务的交付时间。

## 2. 团队建议

| 职能 | 人数 | 重点 |
| --- | ---: | --- |
| 产品/项目 | 1 | 范围、流程、验收、客户协调 |
| UX/UI | 1 | 地图、设备小窗、座舱和航线交互 |
| 前端 | 2 | Vue、Cesium、WebRTC、DRC |
| 后端 | 3 | YOOX 适配、业务领域、IAM、任务 |
| 媒体/IoT | 1 | MQTT、MediaMTX、TURN、弱网 |
| DevOps/SRE | 1 | Docker Compose、监控、容器运维、离线包 |
| QA | 2 | 自动化、协议、性能、弱网、真机 |
| 飞手/安全专家 | 兼职 1-2 | 试飞、风险评审和现场保障 |

精简到 6-7 人可以实施，但建议把周期延长到 24 周以上，不压缩安全和真机验证。

## 3. 里程碑

| 阶段 | 周期 | 交付物 | 退出条件 |
| --- | --- | --- | --- |
| M0 基线与技术验证 | W1-W2 | 需求基线、设备矩阵、协议样本、直播/DRC Spike | 关键设备上线；直播首帧；DRC 仿真链路通过 |
| M1 平台底座 | W3-W5 | 仓库骨架、IAM、多租户、Flyway、CI/CD、Compose、观测 | 租户隔离测试通过；全服务容器启动；无默认 Secret |
| M2 设备态势与直播 | W6-W8 | 地图、设备小窗、OSD、HMS、单/多路直播 | 8 小时直播稳定性；弱网重连通过 |
| M3 虚拟座舱 | W9-W12 | 控制租约、WASD、起飞/返航、云台/相机、安全状态机 | 排他控制和失联收敛测试通过；受控真机试飞 |
| M4 航线与媒体 | W13-W15 | 航线库、WPML 校验、任务、进度、轨迹、媒体 | 立即/定时/暂停/恢复/取消全流程通过 |
| M5 生产化与试点 | W16-W18 | 公私有 Compose 包、配置指南、API 指南、备份恢复、安全测试 | UAT、文档、灾备、性能、安全和现场试点签收 |

每个里程碑结束应演示真实业务闭环，而不是只检查代码完成度。

## 4. 详细工作分解

### M0：基线与技术验证

- 冻结 Demo 基线，梳理当前未提交改动。
- 收集机型、固件、负载、镜头和协议能力。
- 脱敏保存 MQTT 上线、OSD、直播、DRC、航线和 HMS 样本。
- 验证 RTSP、WHEP、TURN 和公网/内网网络条件；记录 RTMP、GB28181 的上云协议能力，但不纳入
  P0 实现和真机验收。
- 验证 DRC 进入/退出、Topic、ACL、频率、延迟和异常。
- 确认源码授权、地图授权和远控合规责任。

### M1：平台底座

- 建立 Maven/pnpm 工程、编码规范、分支和版本策略。
- 建立组织、项目、用户、角色和资源权限。
- 接入 Spring Security，建立令牌轮换和密码策略。
- 建立 Flyway、审计 Outbox、幂等记录和统一错误码。
- 接入日志、指标、Trace、Secret 扫描、依赖扫描和镜像构建。
- 建立设备模拟器和协议契约测试流水线。
- 建立全服务 Dockerfile、Compose profiles、`.env.example`、健康检查和资源限制。
- 建立配置指南、API 指南、OpenAPI 和 AsyncAPI 的同步生成流水线。

### M2：设备态势与直播

- 迁移 YOOX 设备拓扑、OSD、state、HMS 和在线状态。
- 实现能力快照和能力驱动 UI。
- 建设 Cesium 项目地图、设备小窗、轨迹和告警。
- 建设直播会话服务、媒体节点目录、WHEP 播放器和弱网恢复。
- 实现 RTSP 设备推流接入，不启用 RTMP、GB28181 接入代码、监听端口和前端选项。
- 增加随机流路径、短时播放令牌、无人观看自动停流。
- 完成单路、四分屏和多用户观看资源统计。

### M3：虚拟座舱

- 建设控制会话、原子租约、精确 MQTT ACL 和心跳。
- 实现飞行检查单、控制权状态机和安全策略。
- 实现 WASD/虚拟摇杆、起飞到点、指点飞行、返航。
- 实现云台、拍照、录像、镜头和变焦能力。
- 实现延迟、丢包、信号和视频状态可视化。
- 完成浏览器失焦、断网、重复登录、服务重启、设备离线等故障测试。

### M4：航线与媒体

- 建设航线库、版本、标签、导入、下载和预览。
- 实现 KMZ 安全解析、WPML Schema 和设备能力校验。
- 实现立即/定时任务、暂停/恢复/取消、进度和错误映射。
- 实现任务与轨迹、媒体、告警关联。
- 实现 STS、媒体元数据、生命周期和下载鉴权。
- 如列入首期，增加基础航点/面状航线编辑器；高级路线类型进入 P1。

### M5：生产化与试点

- 建设开发、测试、公有云、私有化 Docker Compose 模板和标准离线镜像包。
- 完成 MySQL、Redis、MinIO、EMQX 和媒体服务 HA 演练。
- 完成备份、恢复、升级、回滚、证书轮换和离线安装。
- 完成性能、稳定性、弱网、安全和租户隔离测试。
- 完成配置指南、API 指南、运维、管理员、飞手手册和现场培训。
- 完成 Prometheus、Grafana、Loki、Alertmanager、cAdvisor 监控栈，并输出后期 YOOX Ops Console 接口。
- 小范围白名单上线，观察两周后扩大试点。

## 5. 功能验收

### 5.1 设备与态势

- 遥控器/机巢上线后 10 秒内出现在正确组织和项目。
- 网关、无人机和负载拓扑与设备实际连接一致。
- 地图显示位置、航向、高度、速度、电量、信号和飞行模式。
- 设备离线、低电、HMS 产生告警并可确认、关闭和追溯。
- 无能力的设备不显示或禁用对应操作，并给出原因。

### 5.2 直播

- 平台按 `live_capacity` 展示相机、镜头和最大并发路数。
- RTSP 完成真机开始、播放、镜头/清晰度切换和停流流程。
- 设备业务应答成功但无媒体帧时，页面不得误报“正在播放”。
- 网络短暂中断后播放器能自动恢复；超过策略时间后停止并提示。
- 未授权用户无法猜测路径观看，令牌过期后立即失效。
- 页面退出或最后一个观看者离开后按策略自动停止设备推流。

### 5.3 虚拟座舱

- 同一设备任何时刻只有一个有效控制者。
- 非飞手、非项目成员或未通过二次认证者无法获取控制权。
- 进入座舱必须通过设备、定位、电量、网络、围栏和任务冲突检查。
- WASD、指点、起飞、返航、云台、拍照/录像按能力矩阵工作。
- 浏览器失焦、进程退出、网络断开和租约到期后连续控制量停止。
- 控制延迟超阈值时页面明显告警并禁止新增危险动作。
- 每次控制权变化和高级指令均可按用户、设备、会话和 Trace ID 查询。

### 5.4 航线

- 合法 KMZ/WPML 可导入、预览、版本化；非法压缩包和越权动作被拒绝。
- 不兼容机型/负载的航线在下发前被阻断并显示原因。
- 立即、定时、暂停、恢复、取消、成功和失败状态准确闭环。
- 重复请求不会创建重复任务或重复向设备下发。
- 任务结果能关联航迹、媒体、告警和原始错误码。

### 5.5 公私有部署

- 公有云使用 Docker Compose 完成分节点升级，无核心业务长时间中断。
- 标准私有化 Docker Compose 包在无互联网环境完成安装、运行、备份和升级。
- 离线环境不请求公共地图、公共 CDN、第三方字体或遥测服务。
- 配置切换不需要修改业务代码或维护私有分支。
- 所有业务模块和基础服务均以容器运行，可用 `docker compose` 完成启停、检查和升级。

### 5.6 配置指南与 API 指南

- 项目首次生成时必须同时生成 `docs/配置指南.md` 和 `docs/API指南.md`。
- 配置指南覆盖所有 Compose 服务、profiles、环境变量、端口、证书、数据目录和公私有示例；
  P0 只提供 RTSP 媒体接入配置。
- API 指南覆盖认证、REST、WebSocket、错误码、幂等、分页和完整调用示例，并列出
  RTMP、RTSP、GB28181 能力状态：RTSP 为 P0 已启用，另外两种为后期规划。
- OpenAPI、AsyncAPI、Swagger UI/ReDoc 与 API 指南使用同一份契约源。
- 新增或删除配置项、接口、事件时，CI 能发现指南与代码不一致并阻止发布。
- 每个发布包同时包含代码版本、镜像清单、Compose 文件、配置指南、API 指南和变更记录。

## 6. 非功能验收

### 6.1 性能基线

- 100 台设备持续 OSD 上报 8 小时，无消息堆积和明显内存增长。
- 20 路并发直播、100 个观看会话下，控制面 API 仍满足目标延迟。
- 5 路并发 DRC 时控制租约和 ACL 无串话、无越权。
- WebSocket 断线重连不产生重复事件或跨项目数据。
- 1 GB 航线/媒体相关大文件操作不占满应用堆内存；实际文件大小上限应另行设定。

### 6.2 稳定性和故障注入

至少覆盖：

- MQTT Broker 主节点切换。
- Redis 主从切换和控制租约恢复。
- MySQL 短时不可用和重连。
- MediaMTX 重启、WHEP 会话中断、TURN 不可用。
- 设备重复上线、乱序/重复 MQTT 消息、过期应答。
- NTP 偏差、浏览器刷新、用户强制退出、应用滚动升级。
- Compose 服务重建、容器异常退出、节点磁盘不足和跨节点网络中断。

### 6.3 安全

- OWASP ASVS L2 核心项通过。
- SAST、DAST、SCA、镜像扫描无未豁免的高危/严重问题。
- 代码、镜像、日志和前端资源中无长期密钥与默认密码。
- 租户水平/垂直越权用例全部失败。
- MQTT ACL、对象存储 STS、WHEP 令牌均符合最小权限。
- 审计日志不能通过普通管理员 API 修改或删除。

### 6.4 恢复

- 完成一次从备份恢复到空环境的演练。
- 业务主数据满足 RPO 15 分钟、RTO 2 小时目标。
- 对象存储恢复后能校验数据库记录与文件完整性。
- 升级失败能按文档回滚，数据库迁移有兼容窗口。

### 6.5 容器运维

- `docker compose ps` 与平台健康检查对服务状态判断一致。
- 每个容器具备健康检查、日志轮转、资源上限、重启策略和持久卷声明。
- Prometheus 能采集主机、容器、应用、数据库、MQTT、媒体和对象存储指标。
- Grafana、Loki、Alertmanager 可完成健康看板、日志检索和告警通知。
- 后期 YOOX Ops Console 通过受限 Agent 管理容器，不把 Docker Socket 直接暴露给浏览器。

## 7. 真机测试分级

| 等级 | 环境 | 允许内容 |
| --- | --- | --- |
| L0 | 设备模拟器 | 所有协议、异常和并发自动化 |
| L1 | 真机不装桨/不上电机 | 上云、直播、相机、云台、控制 Topic |
| L2 | 室内防护/系留 | 低高度控制、失联、租约和应急动作 |
| L3 | 合规封闭场地、视距内 | 起飞、指点、航线、返航、弱网 |
| L4 | 受控生产试点 | 白名单设备、限定区域、现场安全员 |

任何等级失败都必须回退到前一级复现和修复，不允许用生产飞行替代协议测试。

## 8. 上线门禁

同时满足以下条件才能开放生产远控：

- 首批机型和固件在能力矩阵中标记为“已验证”。
- 远控故障注入和失联收敛测试通过。
- 组织、飞手、项目和设备白名单配置完成。
- 操作审计、告警和现场应急流程已演练。
- 安全负责人、项目负责人和飞手共同签署放行。
- 生产环境已启用 TLS、备份、监控和证书/Secret 轮换。
- 配置指南、API 指南、OpenAPI/AsyncAPI 和实际部署版本已完成一致性校验。
