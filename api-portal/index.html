基础介绍

YOOX Cloud GCS 是一套可容器化私有部署的网页云端地面站，基于上云 API 的设备协议，为无人机、遥控器与机巢提供设备管理、实时直播、远程控制、航线任务与媒体归档能力。本节介绍平台定位、系统架构与接口通用约定。

平台简介

YOOX Cloud GCS 面向行业无人机的云端统一接入与作业场景，核心能力包括：

  • 设备管理：网关（遥控器/机巢）与子设备（飞行器/负载）的绑定、拓扑、属性与在线状态。
  • 实时直播：设备侧以 RTSP 推流，服务端经 MediaMTX 转封装为 WebRTC，浏览器通过 WHEP 会话播放。
  • 虚拟座舱 / 远程控制：DRC（Direct Remote Control）指令飞行，含控制权租约、心跳与安全联锁。
  • 航线任务：上传 KMZ 航线文件、创建与调度飞行任务、跟踪进度并回传媒体。
  • 媒体归档：媒体文件入对象存储，短时授权 URL 访问。
协议边界：上云 API 的推流能力矩阵包含 RTMP、RTSP、GB28181。当前运行版本仅开放 RTSP 入流，其余为后期能力。

系统架构

平台采用前后端分离 + 容器编排。设备通过 MQTT 接入消息代理，Web 控制台与后端服务通过 HTTP / WebSocket 交互，媒体与对象存储独立成栈：

设备 / 机巢 — MQTT —▶ EMQX ◀—▶ Cloud Service（Spring Boot） ◀—▶ Web 控制台（Vue3）
设备 RTSP —▶ MediaMTX — WHEP —▶ 浏览器 WebRTC ｜ MinIO 对象存储
组件职责
Cloud Service业务 API、设备物模型、鉴权、DRC 控制、航线任务编排
EMQX设备与云端 MQTT 消息代理，基于 Redis 的 Topic ACL
MediaMTXRTSP 入流转 WebRTC（WHEP）出流
MySQL / Redis业务持久化 / 会话、缓存、OSD 与 ACL
MinIO航线与媒体对象存储，签发短时访问凭据

接口通用约定

HTTP API 统一由 Web 入口反向代理。以下示例默认基地址：

BASE_URL=http://<host>:<http-port>

除登录、令牌刷新、健康检查与 OpenAPI 外，请求须携带鉴权头：

x-auth-token: <access_token>
Content-Type: application/json

统一响应信封：

{
  "code": 0,
  "message": "success",
  "data": {}
}

code=0 表示业务成功；HTTP 401 或业务 code=401 表示令牌无效。调用方必须同时检查 HTTP 状态码与业务 code。

登录与鉴权

账号分两类：flag=1 为 Web 账号，flag=2 为 Pilot（遥控器）账号。登录成功返回 access_token、workspace_id 及用户信息。

curl -sS "$BASE_URL/manage/api/v1/login" \
  -H 'content-type: application/json' \
  -d '{"username":"admin","password":"<password>","flag":1}'

令牌刷新：

curl -sS -X POST "$BASE_URL/manage/api/v1/token/refresh" \
  -H "x-auth-token: $TOKEN"
令牌机制：令牌为 HMAC-SHA256 签名的 JWT，默认有效期 86400 秒。签名密钥由部署侧通过环境变量注入；修改密钥会使既有 Web 与 DRC 会话立即失效。

快速开始

  1. 调用登录接口获取 access_token 与 workspace_id。
  2. 拉取设备拓扑：GET /manage/api/v1/devices/{workspace_id}/devices。
  3. 查询直播能力并启动 RTSP 视频源，前端用返回的 WHEP URL 播放。
  4. 如需远控，进入 DRC 流程获取控制权与短时 MQTT 凭据。
  5. 上传 KMZ 航线并创建飞行任务，通过 WebSocket 跟踪进度。

功能集合 / 遥控器功能

功能集合 · 遥控器功能

遥控器（Pilot）侧的核心是「把飞行控制权安全地交给云端网页」。本节围绕控制权管理、DRC 指令飞行、指令控制与负载控制展开，所有能力均以设备能力上报为准动态开放。

遥控器账号接入

遥控器以 Pilot 账号（flag=2）登录，成功后获得平台下发的 MQTT 接入地址与设备账号；设备侧据此建立与消息代理的长连接并上报拓扑。

curl -sS "$BASE_URL/manage/api/v1/login" \
  -H 'content-type: application/json' \
  -d '{"username":"<pilot_user>","password":"<password>","flag":2}'

控制权管理

飞行控制权与负载控制权相互独立，均为排他资源。进入远控前必须先抢占对应控制权，避免多端争抢。

方法路径说明
POST/control/api/v1/devices/{sn}/authority/flight获取飞行控制权
POST/control/api/v1/devices/{sn}/authority/payload获取负载控制权

DRC 指令飞行

DRC 是一个有状态的安全流程，生命周期为：

connect ──▶ enter ──▶ MQTT 心跳 / 控制 ──▶ exit
方法路径说明
POST/control/api/v1/workspaces/{workspace_id}/drc/connect获取 MQTT 短时连接配置
POST/control/api/v1/workspaces/{workspace_id}/drc/enter获取控制权并生成精确 Topic ACL
POST/control/api/v1/workspaces/{workspace_id}/drc/exit释放控制权并清理 ACL

连接请求：

{ "client_id": "", "expire_sec": 3600 }

进入 / 退出请求：

{
  "client_id": "<connect 返回值>",
  "dock_sn": "<dock sn>",
  "expire_sec": 3600,
  "device_info": { "osd_frequency": 10, "hsi_frequency": 1 }
}

expire_sec 范围 1800–86400 秒。进入前服务会校验设备在线、飞行状态、任务状态与控制权。连接信息中的 password 为短时 JWT，客户端不得持久化。

安全联锁：控制端应每秒发送心跳，并以 10 Hz 发布 drone_control。窗口失焦、按键释放、MQTT 断开或退出时，必须先发送零杆量再释放控制权。

摇杆控制消息保持设备物模型信封：

{
  "tid": "<uuid>",
  "bid": "<uuid>",
  "timestamp": 1785319200000,
  "method": "drone_control",
  "data": { "seq": 123, "x": 0, "y": 0, "h": 0, "w": 0, "freq": 10, "delay_time": 300 }
}

指令控制

面向机巢/飞行器的通用服务指令与点位飞行：

方法路径说明
POST/control/api/v1/devices/{sn}/jobs/{service_identifier}通用服务指令，如返航
POST/control/api/v1/devices/{sn}/jobs/fly-to-point飞向目标点
DELETE/control/api/v1/devices/{sn}/jobs/fly-to-point取消飞向目标点
POST/control/api/v1/devices/{sn}/jobs/takeoff-to-point起飞到点

云台与负载控制

方法路径说明
POST/control/api/v1/devices/{sn}/payload/commands云台、相机与负载命令
能力驱动：可用的 service_identifier 与负载命令受机型、固件与设备能力限制。前端应按设备能力上报显示，不得把未验证指令作为固定按钮开放。

航线文件格式标准

平台航线以 KMZ 压缩包承载，内部采用基于 KML 的 WPML 航线标记语言描述模板与执行航线。本节说明文件结构、核心元素及配套的航线与任务 API。

KMZ 文件结构

KMZ 本质是一个 ZIP 压缩包，约定目录为 wpmz/，包含两个核心文件：

文件作用
wpmz/template.kml航线模板：作业类型、坐标/高度参考、全局速度、航点与动作模板
wpmz/waylines.wpml执行航线：由模板解算出的、设备可直接执行的具体航点序列
wpmz/res/可选资源目录（如面状航线所需附属数据）
 
mission.kmz
└── wpmz/
    ├── template.kml
    ├── waylines.wpml
    └── res/

WPML 核心元素

WPML 使用 <wpml:*> 命名空间扩展标准 KML。常用元素分为三层：

航线级

  • templateType：作业类型（航点、航带/面状、条带等）。
  • waylineCoordinateSysParam：坐标系与高度模式（相对起飞点 / 海拔 / 相对地表）。
  • autoFlightSpeed：全局自动飞行速度。
  • globalRTHHeight：全局返航高度。

航点级

  • Placemark + Point/coordinates：经纬度坐标。
  • wpml:height / wpml:ellipsoidHeight：航点高度。
  • wpml:waypointHeadingParam：航向控制策略。
  • wpml:waypointTurnParam：转弯模式（协调转弯、顶点等）。

动作级

  • wpml:actionGroup：动作组，绑定触发方式。
  • wpml:action：具体动作（拍照、录像、悬停、云台转动、变焦等）。
模板与执行分离：template.kml 描述「意图」，waylines.wpml 描述「执行」。平台侧或设备侧据模板解算出执行航线，保证不同机型按各自能力落地同一作业意图。

航线与任务 API

方法路径说明
GET/wayline/api/v1/workspaces/{workspace_id}/waylinesKMZ 航线分页
POST/wayline/api/v1/workspaces/{workspace_id}/waylines/file/upload上传 KMZ，字段名 file
DELETE/wayline/api/v1/workspaces/{workspace_id}/waylines/{wayline_id}删除航线
POST/wayline/api/v1/workspaces/{workspace_id}/flight-tasks创建飞行任务
GET/wayline/api/v1/workspaces/{workspace_id}/jobs任务分页
PUT/wayline/api/v1/workspaces/{workspace_id}/jobs/{job_id}暂停 / 恢复任务
DELETE/wayline/api/v1/workspaces/{workspace_id}/jobs?job_id=<id>取消任务

上传 KMZ：

curl -sS "$BASE_URL/wayline/api/v1/workspaces/$WORKSPACE_ID/waylines/file/upload" \
  -H "x-auth-token: $TOKEN" \
  -F 'file=@mission.kmz'

创建任务核心字段：

{
  "name": "园区巡检-001",
  "file_id": "<wayline id>",
  "dock_sn": "<dock sn>",
  "wayline_type": 0,
  "task_type": 0,
  "rth_altitude": 100,
  "out_of_control_action": 0,
  "min_battery_capacity": 60,
  "min_storage_capacity": 1024
}

rth_altitude 范围 20–500 米，最低电量范围 50–90。定时任务还需 task_days、task_periods。枚举实际值以在线 OpenAPI 与设备能力为准。

校验要点：创建任务前应确认 KMZ 与目标机型匹配、返航高度高于航线区域障碍、电量与存储阈值合理、机巢时间已同步。

Enterprise 上云

Enterprise 上云描述企业级设备如何通过 MQTT 物模型接入平台。本节说明接入架构、Topic 体系、消息信封与设备上线数据流。

接入架构

设备分为「网关设备」与「子设备」：网关（遥控器或机巢）直接建立 MQTT 连接，子设备（飞行器、负载）经由网关代理上云。平台按网关序列号（gateway_sn）组织 Topic。

子设备（飞行器/负载） —▶ 网关（机巢/遥控器） — MQTT —▶ 平台（EMQX + Cloud Service）

应用凭据

设备侧与平台侧须使用一致的上云开发者应用信息：

配置项说明
APP_ID上云开发者应用 ID
APP_KEY上云开发者应用 Key
APP_LICENSE上云应用 License
凭据一致性：这三个值需与设备端使用的开发者应用一致。修改后需重启后端服务使配置生效。

MQTT Topic 体系

设备与平台围绕网关序列号约定一组 Topic：

sys/product/{gateway_sn}/status            # 上下线状态
thing/product/{gateway_sn}/requests        # 设备发起的请求
thing/product/{gateway_sn}/state           # 设备状态 / 属性
thing/product/{gateway_sn}/events          # 事件上报
thing/product/{gateway_sn}/services_reply  # 服务调用应答

平台下行的服务与属性 Topic 由 SDK 按设备序列号生成。

消息信封

物模型消息统一采用如下信封，请求与应答必须关联同一事务 ID（tid）：

{
  "tid": "<事务 id>",
  "bid": "<业务 id>",
  "timestamp": 1785319200000,
  "method": "<方法名>",
  "data": { }
}
字段含义
tid事务 ID，用于请求-应答关联
bid业务 ID，标识一次业务流程
timestamp毫秒级时间戳
method方法名，标识消息语义
data业务数据载荷

设备上线数据流

  1. 上线：网关在 sys/product/{gateway_sn}/status 上报上线，平台建立设备拓扑。
  2. 属性 / 状态：设备持续在 state 上报设备属性与能力（如相机/码流能力）。
  3. OSD：飞行器高频上报姿态、位置、电量等遥测（缓存于 Redis）。
  4. 事件：HMS 告警、任务进度等经 events 上报。
  5. 服务调用：平台下发服务指令，设备经 services_reply 应答。
状态推送：平台通过 WebSocket /api/v1/ws 向前端推送设备状态、任务进度、告警与媒体事件，认证参数与消息业务码以在线 OpenAPI / 源码模型为准。

设备管理 API

方法路径说明
GET/manage/api/v1/devices/{workspace_id}/devices设备拓扑
GET/manage/api/v1/devices/{workspace_id}/devices/{device_sn}设备详情
POST/manage/api/v1/devices/{device_sn}/binding绑定设备

安全基线：上线前须修改初始化密码与所有示例密钥，使用 TLS/WSS，限制 MQTT/RTSP 源 IP，管理端口不出公网；不得在日志中记录 JWT、MQTT 密码或对象存储签名 URL。
